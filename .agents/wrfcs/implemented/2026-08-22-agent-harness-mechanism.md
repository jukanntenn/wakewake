# WRFC: The agent harness — wrfcs, layered instructions, skills source, and documentation gates

Status: implemented

English | [中文](2026-08-22-agent-harness-mechanism.zh.md)

## Problem

wakewake had no home for decision rationale. The why of shipped design lived scattered inside PRINCIPLES.md incident narratives and the untracked legacy tree under `.local/specs/`; proposals awaiting review had no durable address, so every non-trivial change re-derived facts and re-litigated settled questions. Around that gap, five standing defects compounded: the instruction corpus was one flat file — root AGENTS.md at 1,439 words plus its byte-copy CLAUDE.md, so every session loaded every area's commands and conventions regardless of task; the copy was kept by a directional sync (scripts/sync_agents.py copied AGENTS.md → CLAUDE.md), which silently clobbered an edit made on the CLAUDE.md side — the stale-overwrites-fresh failure a mirror must never commit; skills were hand-duplicated between `.zcode/skills/` (four) and `.claude/skills/` (three) with no mechanism and had already drifted (`iterating` existed only on the ZCode side); the Markdown corpus was mixed-language with no pairing rule (AGENTS.md and PRINCIPLES.md English, `specs/` Chinese-only, the README pair under `README_zh.md` naming) and no gates — links rotted silently, a spec shipped unindexed (specs/backend/agent-distribution.md), and history narration had nowhere to live; and the agent hooks restated gate commands — `.claude/hooks/format.py` and `lint_stop.py` hard-coded rustfmt/prettier/clippy invocations that duplicated the three prek configs, the exact single-source-of-truth violation PRINCIPLES #6 names, while `.zcode/` had no hooks at all.

## Decision

The mechanism is adapted from two sources read in full: the deepseek-harness reference project and markpost's adaptation of it, whose decision history (`.agents/mrfcs/` in that repo) is the precedent this record follows. Adaptation, not transplantation — each piece names what wakewake keeps, changes, and declines.

**The wrfcs tree.** Records live at `.agents/wrfcs/{proposed,implemented,rejected}/yyyy-mm-dd-topic.md`, the date being the day the topic was first proposed; the tree is the inventory — browse it or grep the repository, no index file to maintain. The tree root carries two documents with orthogonal jobs: [AGENTS.md](../AGENTS.md) holds standing orders only (duplicate check before writing, supersede-never-rewrite, keep the pair in step), [README.md](../README.md) is the single normative contract, and the README pairs as `README.md` + `README.zh.md` while the standing-orders file stays single-file under the agent-instruction exemption. The file format is a fixed header block, a `Status:` line that must agree with the folder, a body opening with `## Problem` written to stand without the solution, and lifecycle-specific continuation — `## Decision` / `## Alternatives considered` / `## Consequences` in the present tense for implemented records (proposal-speak headings rejected by the gate), `## Proposal` / `## Alternatives considered` / `## Acceptance criteria` / `## Risks` for proposed ones, and a frozen body with the verdict on the `Status:` line for rejected ones. Trigger rule: every non-trivial change — behavior, architecture, a contract shared across files, tooling, testing strategy, an on-disk or wire format — adds or updates at least one record in the same change, after grepping the tree for an existing owner. This record is the first wrfc and exercised the mechanism on itself: it was written into `proposed/`, reviewed, and rewritten into this implemented form by the batch that shipped the mechanism.

**The documentation standard.** One home: [docs/AGENTS.md](../../../docs/AGENTS.md) (wakewake had no `docs/` before). It carries the tier map — README, root AGENTS.md, subtree AGENTS.md, PRINCIPLES.md, `specs/`, `docs/`, wrfcs, skills — assigning each fact a single home ("elsewhere, link; never restate"), plus the seven writing rules below, each naming the gate that enforces it. `specs/README.md` remains the specs index and is a pair; wakewake keeps README.md naming where markpost uses `index.md`, because forges render a directory's README.md for free. Operational runbooks under `.local/` stay untracked and out of scope.

**Bilingual pairs, corpus-wide.** Every documentation file ships as `foo.md` beside `foo.zh.md`, equal authority: either side may be authored or edited first, the edited side is the source for that change, and the twin follows in the same change as a minimal patch — never a wholesale re-translation; where a pair substantively disagrees, the side that is wrong is fixed, and neither language wins by default. `README_zh.md` is now `README.zh.md`. Scope is the tracked documentation corpus — the README pair, PRINCIPLES.md, `specs/` including the index, `docs/` content, `.agents/wrfcs/**`, `devops/README.md`, `frontend/README.md`, `backend/crates/agent/README.md` — with exemptions in an exclusions-only manifest (`scripts/doc_languages.manifest.json`): agent instructions (every AGENTS.md/CLAUDE.md/SKILL.md and the skills mirrors), `.zcode/`, and generated files. Pair contract: a language switcher in each side's header region (bare filename), link locale (a `.zh.md` page links `.zh.md` targets and vice versa, the switcher excepted), structural parity (identical heading-depth sequences and byte-identical fenced code blocks, comments included — examples are not translated, so the Chinese-primary specs keep their Chinese-commented blocks on both sides), machine tokens and section headings in English on both sides, and no CJK in English-side prose beyond manifest exemptions. The corpus normalized in one batch of eleven pairs; the staged gate tolerates a not-yet-written twin link target while CI's strict full run owns the end state.

**Layered instructions with budgets.** The root keeps what every session needs — identity, tech stack, the layout map, the cross-area command index (`dev.py`, doc gates), git workflow, cross-area boundaries, one-line pointers to the WRFC and documentation homes, and an "Editing these instructions" section stating the mirror contract — at 710 words under the 800 ceiling. Three subtree files carry workspace-specific orders: [backend/AGENTS.md](../../../backend/AGENTS.md) (cargo commands, migration rules, Rust style, testing contracts) at 371/500, [frontend/AGENTS.md](../../../frontend/AGENTS.md) (pnpm commands, React/TypeScript style, the static-export constraint, Vitest) at 166/300, [e2e/AGENTS.md](../../../e2e/AGENTS.md) at 125/150; a subtree file supplements the root and never repeats it. Budgets are `wc -w` whole-file ceilings in `scripts/doc_budgets.manifest.json`; budgeted files are English-only agent instructions, so `wc -w` suffices and no CJK counting is needed; a budgeted file gone missing fails the gate so renames cannot orphan budgets. docs/AGENTS.md carries a 600-word ceiling of its own (454 used).

**Direction-free mirrors.** [scripts/agentlib.py](../../../scripts/agentlib.py), ported from markpost: each AGENTS.md ↔ CLAUDE.md pair (root, backend, frontend, e2e) resolves direction against git HEAD — exactly one side differing from HEAD means that side is copied over the stale twin and staged by the gate; equal contents pass; both sides changed and disagreeing is a conflict the tooling refuses to guess through, failing with the sides, the fix command, and the manual reconciliation steps; a side absent from HEAD bootstraps its twin. mtime is rejected as a direction signal because clone and checkout reset it. `scripts/check_agent_instructions.py` is the self-healing prek pre-commit gate, `scripts/sync_agent_instructions.py` the manual fixer, and the directional `scripts/sync_agents.py` plus its `agents-sync` hook are gone. The port hardened one markpost defect the drill exposed: `sync_skills` deleted the mirrors before checking the source, so a missing source destroyed both mirrors with nothing to rebuild from — the source is now guarded before any `rmtree`.

**Skills.** `.agents/skills/` is the source; `.zcode/skills/` and `.claude/skills/` are byte mirrors rebuilt wholesale by the sync script and verified by the gate — markpost records this promotion of `.agents/` as future work, but wakewake created `.agents/` in this very change, so it landed directly (and the former drift, `iterating` missing from the Claude copy, is gone: both mirrors now carry all five skills). New skill: `writing-wrfcs` (when a record is owed, the format, lifecycle moves, and the pair duty). The `commit` skill carries the pair-bundling rules — README pair, wrfc pair, spec pair, staged as one logical unit, never one-sided — and the new mirror contract. `iterating` and `shipping` are unchanged; a dedicated `doc-standards` skill stays signal-gated: every rule has a gate and a root pointer.

**Seven gates, one orchestrator.** Stdlib-only scripts sharing [scripts/doclib.py](../../../scripts/doclib.py) (shape-preserving masking so diagnostics address real line numbers; GitHub-compatible heading slugs), aggregated in order by [scripts/doc_sync.py](../../../scripts/doc_sync.py), each independently runnable and restrictable to given files: `verify_md_links.py` (relative targets exist; `#fragment` resolves against the target's headings), `verify_md_wrap.py` (one physical line per prose paragraph), `verify_md_current.py` (no history narration in README/docs/specs — the wrfcs own history), `verify_specs_index.py` (the specs index complete in both directions, one row per pair by stem), `verify_wrfc_format.py` (skeleton, Status-folder agreement, lifecycle headings, the `.zh.md` twin present), `verify_doc_pairs.py` (completeness both directions, switcher, link locale, structural parity, English-side purity, manifest validation), `verify_doc_budgets.py`. The root [prek.toml](../../../prek.toml) carries `doc-check` in the lint group at the pre-commit stage over staged Markdown, excluding `.zcode/` — staged-only because prek stashes unstaged changes during hook runs; the full corpus runs in CI through the same group invocation.

**Hooks delegate to prek.** PostToolUse runs `prek run --group format --files <file>` on the just-edited file; Stop runs `prek run --group lint --all-files` with a once-per-turn guard. The format group is now the mutating tier — backend `cargo fmt`, frontend `prettier --write`, root `ruff format` for Python — while the read-only checks (`cargo fmt --check`, `prettier --check`) moved to the lint group as `fmt-check`/`format-check`, each defined **before** its fixer in the project config so CI's group invocation checks the clean tree before any fixer touches it; CI's coverage is unchanged (drift still fails). Three thin adapters are hand-maintained, differing only in payload shape: `.claude/hooks/` (snake_case payload), `.zcode/hooks/` (camelCase payload; registered at user level because ZCode v2.1.0 strips workspace-scope hooks, with the one-time registration documented in `.zcode/README.md`), and `.codex/hooks/` (parses apply_patch paths). The old `format.py`/`lint_stop.py` and `scripts/sync_hooks.py` are deleted. CI's lint.yml dropped `**/*.md`, `docs/**`, and `specs/**` from its workflow-level `paths-ignore`, so documentation changes now trigger the root lint job (doc-check); backend/frontend jobs stay behind the dorny/paths-filter.

## Alternatives considered

**Port the reference machinery wholesale** — the TypeScript gate chain, a scheduler with `needs`/`after` edges, per-note `.md` + `.zh.md` + `.i18n.yaml` triplets, a sealed archive: roughly 5,300 lines of tooling serving about 1,150 pairs. Lost: wakewake's corpus is an order of magnitude smaller, the repo has no root Node toolchain, and the Python-stdlib suite covers every rule adopted; pieces arrive on trigger signals only, the recorded discipline of both precedents.

**Rules without gates.** Lost: undisciplined drift is the exact failure the gates exist for; every rule in the standard names the gate that enforces it, and a rule without machinery re-creates the failure it bans.

**Locale directories (`en/` and `zh/` subtrees).** Lost: side-by-side pairs keep the twin in the same diff and the same review, and let a link switch locale by suffix; directories split each page from its own maintenance and turn the link graph into two trees to keep honest.

**English primary, Chinese as translation.** Lost: the maintainer works in Chinese and `specs/` was Chinese-native; primacy would demote the side most likely to be authored first and re-file existing Chinese pages as derivatives of translations that did not exist.

**Keep the `README_zh.md` naming.** Lost: `.zh.md` is the convention the wrfc tree, the format gate's filename regex, and every new pair share; two spellings for one idea is its own drift.

**Grandfather the single-language stock.** Lost: a two-class corpus whose Chinese or English half permanently misses content, for a bounded one-time cost — eleven pairs, the largest being `specs/backend/configuration.md` at about 300 lines.

**Signal-gate the wrap and budget gates.** Lost on budgets: a 1,439-word root was the accretion signal, already fired; wrap rides the same stdlib suite and its one-time reflow was bounded by the normalization that landed anyway.

**Keep the directional sync.** Lost: directionality is the defect, not a tuning choice — whichever side is named secondary has its edits silently reverted by the fixer, precisely on the side whose tool loads it and whose agent therefore most likely edited it.

**Symlink mirrors.** Lost: git stores a symlink as a mode-120000 blob holding the target path; a Windows checkout without `core.symlinks` materializes CLAUDE.md as a regular file containing nine bytes, and nothing constrains contributors to Unix-like checkouts.

**mtime-based direction detection.** Lost: clone and checkout reset mtimes to now, making both sides equally new; content comparison against HEAD is deterministic and depends on no filesystem state.

**`.zcode/skills/` (or `.claude/skills/`) as the skills source.** Lost: `.agents/` is the ecosystem load path for agent resources and this change creates it anyway; promoting it now avoids a migration markpost had to record as future work, and both tool directories need byte copies regardless of which is authoritative.

**The documentation standard inside `specs/README.md`.** Lost: an index and a standard are different jobs; merging them turns the one-page index into the standing-orders page, and the index must remain a table a spec author can update mechanically.

**One wrfc per sub-mechanism, as markpost's four-record history did.** Lost: those records landed as separate change-sets over days, each with its own review; this mechanism landed as one batch and gets one record whose sections run as deep as the batch.

## Consequences

All seven gates run green over the normalized corpus in both modes — staged (pre-commit) and full (CI-equivalent `doc_sync.py` with no arguments): 40 files with every relative cross-link and fragment resolving, 40 with no hard-wrapped prose, 17 current-state-only, 3 spec pairs listed in both indexes, 11 bilingual pairs verified for completeness, switchers, link locale, structure, and purity, 5 budgeted files within their ceilings, and this pair following the wrfc format. The prek groups were exercised end to end: the root lint group runs `doc-check` (full corpus) and `actionlint` green; the check group runs the builtin hygiene hooks plus `agent-instructions-sync` green; the format group's first run pulled three legacy Python scripts into ruff's formatting (previously only AI-edited files were ever formatted) — a mechanical reflow verified content-neutral. `README.zh.md` is renamed with every inbound link updated; the skills mirrors are byte-identical to `.agents/skills/`; normalization corrected in passing what the gates flagged — three history-narration phrases in `devops/README.md` and one spec, a broken `../../releases` link in the agent README, README references to spec directories that do not exist in the tracked tree, and a `.local`-only spec link that would have failed CI's link gate. The mirror drill surfaced two truths now part of the contract: direction detection reads git HEAD, so while a change-set is uncommitted any second-side edit registers as a both-sides conflict the tooling refuses to guess through (the self-heal path operates once the batch is committed), and the port closed markpost's rmtree-before-source defect in `sync_skills`. Accepted costs: structural parity proves shape, not meaning — a sloppy twin passes green, so review carries semantics; staged-only pre-commit gating means full-corpus truth lives in CI; budget ceilings invite raise-churn, absorbed by headroom and the documented raise path; ZCode's workspace-hook stripping makes user-level hook registration a manual per-machine step (`.zcode/README.md` is the mitigation); the fmt-check-before-fmt definition order in backend/frontend prek.toml is load-bearing for CI's group invocation and must survive future edits; and the ported `used to` narration phrase also matches the passive voice, so the corpus words such statements actively ("Email links are built from it"), a constraint future English prose inherits.
